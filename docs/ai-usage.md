# AI 활용 내역

PlaNU 개발 과정에서는 GPT와 Codex를 주요 생성형 AI 도구로 활용했다. AI는 요구사항을 기능 단위로 나누고, 백엔드 API 구조와 프론트엔드 화면 흐름을 설계하며, 반복적인 코드 초안과 테스트 케이스를 작성하는 데 사용했다. 특히 자연어 선호 조건 파싱, 전공 과목 업로드/확인 흐름, 시간표 후보 생성 및 검증 로직, Flutter 화면과 FastAPI 서비스 계층을 구현할 때 코드 예시와 개선 방향을 제안받았다.

AI의 활용 범위는 프로젝트 전반의 생산성 보조에 한정했다. 핵심 서비스 정책, 데이터 구조, 예외 처리 방식, 사용자 흐름은 팀이 직접 검토해 결정했으며, AI가 생성한 코드는 그대로 반영하지 않고 기존 아키텍처와 맞는지 확인한 뒤 필요한 부분만 선택적으로 수정했다. 부산대학교 수강편람 데이터 처리, 캠퍼스 이동 규칙, 시간표 충돌 판정처럼 정확성이 중요한 부분은 실제 도메인 규칙과 테스트 결과를 기준으로 재검토했다.

AI 생성 코드는 기능별 단위 테스트와 통합 테스트를 통해 검증했다. 백엔드에서는 `pytest` 기반 테스트로 과목 파싱, 선호 조건 파싱, 시간표 후보 생성, 랭킹, 세션 흐름, API 응답을 확인했다. 프론트엔드에서는 Flutter 위젯 테스트와 주요 화면 흐름 테스트를 통해 화면 전환, 입력값 반영, 결과 표시가 의도대로 동작하는지 검증했다. LLM을 사용하는 기능은 고정 fixture 기반 테스트와 live smoke test를 분리해, 일반 로직의 재현성과 실제 모델 호출 시의 동작을 함께 확인했다.

검증 과정에서 발견된 문제는 AI에게 다시 수정 방향을 요청하기보다 실패 원인을 먼저 사람이 분석했다. 이후 프롬프트, 스키마, 정규화 로직, 예외 처리, UI 상태 관리 중 어느 부분을 고쳐야 하는지 범위를 좁혀 수정했다. 수정 후에는 관련 테스트를 다시 실행하고, 회귀 가능성이 있는 경우 기존 fixture나 테스트 케이스를 추가해 동일한 문제가 반복되지 않도록 했다.

따라서 AI는 코드 작성자라기보다 설계 검토, 초안 생성, 테스트 보강을 돕는 페어 프로그래밍 도구로 사용되었다. 최종 반영 여부와 품질 판단은 팀의 코드 리뷰, 실행 결과, 테스트 통과 여부를 기준으로 결정했다.
